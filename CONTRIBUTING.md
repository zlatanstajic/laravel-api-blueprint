# Contributing

For suspected vulnerabilities, follow [SECURITY.md](SECURITY.md) and report privately rather than opening a public issue.

Contributions are welcome. To propose a change:

1. **Fork and branch.** Fork the repository, then create a branch off `master`. Branch names are kebab-case: `issues/12-short-description`, never `issues/12_short_description`. Open an issue first for larger changes or anything that affects the architecture, authentication, ownership rules, or public API.
2. **Set up the project.** Follow the local installation instructions in [README.md](README.md). Configure local values in `.env`, but never commit environment files, credentials, tokens, or other local configuration. Run `composer setup` only when it is safe to recreate and seed your configured development database: the command uses `migrate:fresh` and deletes its existing data.
3. **Preserve the application boundaries.** Controllers validate requests, delegate to constructor-injected services, and shape responses through the base controller and API resources; services contain business logic; repositories are the only layer that accesses Eloquent models. Keep every todo route behind `auth:sanctum`: ownership relies on the `UserScope` global scope, which is intentionally inactive when no user is authenticated. Set `user_id` from the authenticated user in the controller and never accept it as client input. Add database changes as new migrations rather than editing migrations that may already have run.
4. **Match project conventions.** Start every PHP file with `declare(strict_types=1);`, use explicit parameter and return types, follow the style and docblock density of neighboring files, and create Laravel classes with the appropriate `php artisan make:* --no-interaction` command. Keep API output in [`TodoResource`](app/Http/Resources/TodoResource.php) and user-facing strings in both the [English](resources/lang/en/messages.php) and [Serbian](resources/lang/sr/messages.php) translation files. Add project-specific spellings to [`peck.json`](peck.json). If the Open Graph artwork changes, edit [`scripts/gen-og-image.py`](scripts/gen-og-image.py) and regenerate the PNG instead of editing it directly.
5. **Test every path.** Add or update PHPUnit tests for each behavioral change, including success, failure, conditional, exception, and early-return paths. Unit tests use hand-written stubs and extend `PHPUnit\Framework\TestCase`; follow that pattern unless a genuine HTTP integration test requires `Tests\TestCase`, Sanctum authentication, and database setup. Run the smallest affected test first, such as `php artisan test --compact tests/Unit/TodoServiceTest.php`, then run `composer test`. The complete gate checks Rector, Peck, Pint, PHPStan, PHPUnit, and a mandatory 100% coverage threshold. Use `composer fix` for supported automatic fixes.
6. **Open a pull request.** Push your branch and open a PR against `master` with a clear explanation of what changed, why it changed, and how it was verified. Keep the PR focused, include any API or translation updates required by the change, and make sure `composer test` passes. The installed pre-commit hook runs the same gate; do not bypass it to submit failing changes.
